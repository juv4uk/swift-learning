# Урок 10. SwiftUI: інтерфейс і стан

## Мета

Навчитися будувати нативний інтерфейс, який реагує на дії користувача. Наприкінці уроку ти зможеш створити невеликий екран трекера навчання: показати список тем, відфільтрувати його, додати запис і відкрити деталі.

## Що ти вивчиш і навіщо

SwiftUI описує інтерфейс як результат роботи коду. Ти не малюєш кожен елемент вручну: описуєш, **що** має бути на екрані, а SwiftUI оновлює його, коли змінюються дані.

У цьому уроці ти навчишся:

- читати базову структуру SwiftUI-застосунку (`App`, `Scene`, `View`, `body`);
- розкладати елементи у вертикальний, горизонтальний і накладений контейнери;
- зберігати локальний стан у `@State` і передавати його дочірньому екрану через `@Binding`;
- показувати колекції в `List` і `ForEach` зі стабільною ідентичністю;
- обирати між `NavigationStack` і `NavigationSplitView`;
- збирати форми, відкривати `sheet` та показувати `alert`.

Ці поняття потрібні майже в кожному застосунку: список покупок, нотатки, планер або Study Tracker працюють за подібною схемою.

## Теми

- `App`, `Scene`, `View`, `body`, модифікатори та Preview.
- `VStack`, `HStack`, `ZStack`, `Spacer`, `padding`, `frame`.
- `@State` як локальний стан та `@Binding` для передавання керованого значення.
- `List`, `ForEach`, ідентичність елементів.
- `NavigationStack` і `NavigationSplitView` — вибір навігації для сценарію.
- `Form`, `TextField`, `Picker`, кнопки, `sheet`, `alert`.

## Перший приклад: екран, який реагує на натискання

Створи в Xcode проєкт iOS із шаблоном **App**. Файл із головним екраном зазвичай містить тип `ContentView`. Заміни його вміст таким кодом:

```swift
import SwiftUI

struct ContentView: View {
    @State private var completed = false

    var body: some View {
        VStack(spacing: 16) {
            Text("SwiftUI")
                .font(.title)

            Text(completed ? "Тему завершено" : "Тема в роботі")

            Button(completed ? "Повернути в роботу" : "Позначити завершено") {
                completed.toggle()
            }
        }
        .padding()
    }
}

#Preview {
    ContentView()
}
```

### Як читати цей код

1. `import SwiftUI` підключає типи та елементи SwiftUI.
2. `struct ContentView: View` оголошує екран. `View` означає, що тип може описати свій інтерфейс.
3. `@State private var completed = false` — змінне значення, яким володіє цей екран. Спочатку тема не завершена.
4. `body` повертає опис інтерфейсу. Тут кореневим контейнером є `VStack` — вертикальний стовпчик.
5. Тернарний оператор `condition ? valueIfTrue : valueIfFalse` вибирає різний текст залежно від `completed`.
6. `Button` має напис і замикання — код, який виконується після натискання. `toggle()` змінює `true` на `false` або навпаки.
7. Коли змінюється `@State`, SwiftUI повторно обчислює `body` і показує актуальний текст. Ти не викликаєш окрему команду «перемалювати екран».
8. `#Preview` дає Xcode дані для Canvas Preview. Це зручний швидкий перегляд, але застосунок можна також запустити кнопкою ▶ (Run) у верхній панелі.

## Основні терміни без зайвої теорії

- **View** — опис частини інтерфейсу: тексту, кнопки, списку або цілого екрана.
- **`body`** — обов’язкова властивість `View`, у якій описано його вміст.
- **Модифікатор** — виклик після крапки, наприклад `.padding()` або `.font(.title)`. Він створює змінену версію View, а не «виправляє» його на місці.
- **Стан** — дані, від яких залежить вигляд або поведінка екрана. Наприклад, обраний фільтр чи текст у полі.
- **`@State`** — спосіб зберігати простий локальний стан View. Коли значення змінюється, пов’язані View оновлюються.
- **`@Binding`** — двостороннє підключення до стану, яким володіє інший View. Дочірній View може читати значення і змінювати його, але не створює власну незалежну копію.
- **Контейнер** — View, який розміщує інші View, наприклад `VStack` або `List`.

## Розкладка інтерфейсу

`VStack` розміщує елементи зверху вниз, `HStack` — зліва направо, а `ZStack` накладає їх один на одного. `Spacer()` займає вільне місце, тому його часто використовують, щоб розсунути елементи по краях.

```swift
HStack {
    Text("Прогрес")
    Spacer()
    Text("3 з 5")
}
.padding(.horizontal)
```

`.padding()` додає внутрішній відступ навколо View. `.frame(maxWidth: .infinity, alignment: .leading)` дозволяє View зайняти доступну ширину та вирівняти вміст ліворуч. Застосовуй модифікатори в порядку, який відповідає бажаному результату: відступ, накладений до або після іншого модифікатора, може дати різний вигляд.

## Стан і `@Binding`

Нехай батьківський екран зберігає, чи завершена тема, а дочірній рядок лише показує та змінює це значення:

```swift
struct TopicRow: View {
    let title: String
    @Binding var completed: Bool

    var body: some View {
        HStack {
            Text(title)
            Spacer()
            Toggle("Завершено", isOn: $completed)
                .labelsHidden()
        }
    }
}

struct ContentView: View {
    @State private var completed = false

    var body: some View {
        TopicRow(title: "SwiftUI", completed: $completed)
            .padding()
    }
}
```

Символ `$` перед `completed` передає binding — зв’язок із самим значенням, а не його поточну копію. Якщо написати `completed: completed`, це буде лише значення, і `TopicRow` не зможе змінювати стан батьківського View.

## Списки, `ForEach` та ідентичність

Для навчального трекера зручно мати модель із незмінним ідентифікатором:

```swift
import SwiftUI

struct StudyTopic: Identifiable {
    let id = UUID()
    var title: String
    var completed: Bool
}

struct TopicList: View {
    let topics: [StudyTopic]

    var body: some View {
        List {
            ForEach(topics) { topic in
                HStack {
                    Text(topic.title)
                    Spacer()
                    Image(systemName: topic.completed ? "checkmark.circle.fill" : "circle")
                }
            }
        }
    }
}
```

`List` дає готову прокручувану структуру рядків. `ForEach` повторює вміст для кожного елемента. Протокол `Identifiable` і властивість `id` допомагають SwiftUI зрозуміти, який саме рядок додали, змінили або видалили. Не покладайся на позицію в масиві як на постійну ідентичність: після сортування чи видалення позиції змінюються.

Коли список змінюється, дані мають змінюватися там, де ними володіє стан. Для невеликого прототипу це може бути `@State private var topics: [StudyTopic]`. Пізніше модель можна замінити на сховище, але спочатку перевір взаємодію інтерфейсу в пам’яті.

## Навігація та інші елементи форми

`NavigationStack` підходить для послідовного переходу: список → деталі → редагування. `NavigationSplitView` зручно використовувати на ширшому екрані, де список і деталі видно поруч. Вибір залежить від сценарію та розміру екрана, а не від того, який компонент «новіший».

`Form` групує налаштування та поля введення. `TextField` приймає текст через binding, `Picker` дає вибрати один варіант, а `Button` запускає дію. Для тимчасових екранів використовуй `.sheet`, для важливого підтвердження або повідомлення — `.alert`.

```swift
struct AddTopicView: View {
    @Environment(\.dismiss) private var dismiss
    @State private var title = ""
    @State private var status = "В роботі"

    let onSave: (String, String) -> Void

    var body: some View {
        NavigationStack {
            Form {
                TextField("Назва теми", text: $title)
                Picker("Статус", selection: $status) {
                    Text("В роботі").tag("В роботі")
                    Text("Завершено").tag("Завершено")
                }
            }
            .navigationTitle("Нова тема")
            .toolbar {
                ToolbarItem(placement: .confirmationAction) {
                    Button("Зберегти") {
                        let trimmedTitle = title.trimmingCharacters(in: .whitespacesAndNewlines)
                        guard !trimmedTitle.isEmpty else { return }
                        onSave(trimmedTitle, status)
                        dismiss()
                    }
                }
            }
        }
    }
}
```

`@Environment(\.dismiss)` дає доступ до дії закриття поточного екрана, наприклад sheet. Перевірка після `trimmingCharacters(in:)` не дозволяє зберегти назву, яка складається лише з пробілів. Замикання `onSave` повідомляє батьківський екран, що користувач натиснув «Зберегти».

## Як думати над задачею

Перед написанням коду сформулюй стан, дії та екрани:

1. Які дані потрібні одному запису? Для Study Tracker це назва, статус та `id`.
2. Хто володіє масивом записів? Обери один батьківський View, щоб не створювати кілька суперечливих копій.
3. Які дії змінюють дані? Додавання, перемикання статусу, видалення та фільтрування.
4. Що має бути похідним значенням? Наприклад, відфільтрований список можна обчислити з масиву та вибраного статусу, а не зберігати вдруге.
5. Який екран показати першим і як повернутися назад? Спочатку зроби простий шлях список → деталі, а потім додай sheet для створення.

Розділяй задачу на маленькі перевірювані кроки: спочатку покажи тестові дані, потім додай одну дію, і лише після цього переходь до наступної.

## Практичне завдання: Study Tracker

Створи інтерфейс Study Tracker:

1. Головне вікно зі списком навчальних тем.
2. Фільтр за статусом.
3. Форму додавання теми.
4. Детальний екран запису.
5. Редагування статусу та видалення запису.

Почни з тестових даних у пам'яті. Не підключай SwiftData, доки взаємодія інтерфейсу не працює.

### Послідовність роботи

1. У Xcode відкрий проєкт і запусти початковий екран кнопкою ▶. Якщо використовуєш Canvas, натисни Resume, щоб оновити Preview після зміни коду.
2. Створи `StudyTopic` з `id`, `title` і статусом. Додай два-три тестові записи.
3. Покажи записи в `List` через `ForEach`. Переконайся, що кожен рядок має стабільний `id`.
4. Додай `NavigationStack`, заголовок екрана та перехід до деталей натисканням на рядок.
5. Додай `@State` для вибраного фільтра. Зроби `Picker` або меню й відображай лише відповідні записи.
6. Винеси форму створення в окремий View. Передавай дані назад через замикання, перевіряючи непорожню назву.
7. Додай кнопку «Додати», яка відкриває форму через `.sheet(isPresented:)`.
8. На екрані деталей передай потрібний binding, щоб перемикач статусу змінював запис у батьківському масиві.
9. Додай видалення та, якщо дія може бути випадковою, попроси підтвердження через `.alert`.
10. Пройди сценарій від початку до кінця: відкрити список, відфільтрувати, додати, відкрити, змінити статус і видалити тему.

## Типові помилки

- **Зміна локальної копії замість джерела стану.** Рядок показує правильне значення, але список не змінюється. Причина — передано звичайне значення, а не `$binding`. Виправлення: зберігай дані у батьківському `@State` і передавай дочірньому View `@Binding`.
- **Нестабільний `id` у списку.** Рядки «стрибають» або SwiftUI неправильно зберігає їхній стан. Причина — ідентичність залежить від індексу чи створюється наново під час кожного оновлення. Виправлення: додай стабільний `UUID` до моделі та використовуй `Identifiable`.
- **Вічне додавання пробілів як назви.** Поле формально не порожнє, але запис непридатний. Виправлення: обріж пробіли через `trimmingCharacters(in: .whitespacesAndNewlines)` і перевір результат.
- **Занадто великий `body`.** Усе важко читати й налагоджувати. Виправлення: винеси рядок, форму та деталі в окремі `View`, а стан залиш там, де ним володіють.
- **Неправильне очікування від Preview.** Canvas може не оновитися або не показати поведінку реального пристрою. Виправлення: натисни Resume, перевір помилки компіляції та час від часу запускай застосунок через Run на симуляторі.
- **Нечіткі назви кнопок.** «OK» або лише іконка не пояснюють дію. Виправлення: використовуй дієслова («Додати», «Зберегти», «Видалити») і, де доречно, додай текстовий label до іконки для доступності.

## Перевір себе

Відповідай без підглядання в код:

1. Чим `@State` відрізняється від `@Binding`?
2. Чому після зміни `@State` SwiftUI оновлює текст на екрані?
3. Навіщо елементу списку стабільний `id`?
4. Коли обрати `NavigationStack`, а коли `NavigationSplitView`?
5. Де перевірити, що назва нової теми не порожня після обрізання пробілів?
6. Які дії має виконувати користувач у повному сценарії Study Tracker?

Ти готовий рухатися далі, якщо можеш пояснити джерело стану, самостійно додати запис без порожньої назви, змінити статус через binding, перейти до деталей і видалити запис. Додатково перевір клавіатуру або VoiceOver: основні дії мають бути зрозумілими не лише за кольором чи іконкою.

## Критерії готовності

- [ ] Можу пояснити, звідки SwiftUI отримує стан і чому View оновлюється.
- [ ] Список використовує стабільну ідентичність елементів.
- [ ] Форма перевіряє порожню назву.
- [ ] Навігація та редагування працюють.
- [ ] Інтерфейс має зрозумілі назви кнопок і базову клавіатурну доступність.
