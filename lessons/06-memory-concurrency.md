# Урок 6. ARC та конкурентність

## Що ти вивчиш і навіщо

У цьому уроці ти навчишся відповідати на два практичні запитання:

1. Чому об'єкт-клас досі займає пам'ять і як Swift розуміє, коли його можна звільнити?
2. Як запускати роботу, що може чекати на результат, і безпечно змінювати спільний стан?

Ці знання потрібні, коли програма працює із мережевими запитами, таймерами, файлами або кількома задачами одночасно. Мета не в тому, щоб вручну керувати кожним байтом пам'яті, а в тому, щоб бачити власника даних і межі безпечної зміни стану.

## ARC

Swift використовує **Automatic Reference Counting (ARC)** для керування пам'яттю екземплярів класів. `class` створює посилальний тип: дві змінні можуть вказувати на один і той самий екземпляр. ARC рахує сильні посилання на цей екземпляр. Коли сильних посилань не залишилося, Swift звільняє його пам'ять.

**Сильне посилання** — звичайне посилання на властивість або змінну-клас. Воно утримує об'єкт живим. Проблема виникає, якщо два об'єкти сильно посилаються один на одного: кожен утримує іншого, навіть коли ззовні до них уже немає доступу. Це називається **цикл сильних посилань**.

```swift
final class Person {
    let name: String
    var apartment: Apartment?

    init(name: String) {
        self.name = name
    }

    deinit {
        print("Звільнено \(name)")
    }
}

final class Apartment {
    let number: Int
    weak var tenant: Person?

    init(number: Int) {
        self.number = number
    }
}

var olena: Person? = Person(name: "Олена")
var apartment: Apartment? = Apartment(number: 12)
olena?.apartment = apartment
apartment?.tenant = olena
olena = nil
apartment = nil
```

### Покроковий розбір

1. `olena` сильно утримує `Person`, а `apartment` сильно утримує `Apartment`.
2. `Person.apartment` — сильне посилання, тому людина утримує квартиру.
3. `Apartment.tenant` позначено `weak`, тому квартира може знати свого мешканця, але не утримує його.
4. Після `olena = nil` власник `Person` зникає. ARC звільняє `Person`, а `tenant` автоматично стає `nil`.
5. Після `apartment = nil` зникає останнє сильне посилання на `Apartment`.

`weak` працює лише з опційним посиланням, бо воно може автоматично стати `nil`. Починай із `weak` там, де життєвий цикл пов'язаного об'єкта не гарантований: наприклад, делегат часто не повинен утримувати свого власника.

`unowned` — посилання без утримання об'єкта, але воно не стає `nil`. Його можна читати лише тоді, коли об'єкт гарантовано існує довше за посилання. Якщо ця гарантія помилкова, звернення до `unowned` може завершити програму з помилкою. Для початку безпечніше обрати `weak`.

`deinit` — спеціальний блок класу, який виконується перед звільненням екземпляра. Використовуй його для спостереження під час навчання або для звільнення ресурсів, якщо це справді потрібно; не треба вручну «видаляти» звичайні Swift-об'єкти.

## async/await

`async` позначає асинхронну функцію, `await` — місце, де виконання може призупинитися, очікуючи результат. Поки функція чекає, потік не обов'язково заблокований: інша робота може отримати можливість виконатися.

```swift
func loadTitle() async -> String {
    "Перший асинхронний урок"
}

let title = await loadTitle()
```

У цьому маленькому прикладі функція ще не робить повільної операції, але її можна викликати лише з асинхронного контексту. `await` не означає «запусти в іншому потоці» — він означає «тут можна чекати результат». Якщо операція може завершитися помилкою, сигнатура буде на кшталт `async throws`, а виклик потребуватиме `try await`.

## Task і actor

`Task` запускає асинхронну роботу. Наприклад, усередині асинхронного контексту можна написати:

```swift
Task {
    let title = await loadTitle()
    print(title)
}
```

`actor` ізолює змінний стан, щоб конкурентні задачі не змінювали його неконтрольовано. Доступ до його ізольованих властивостей і методів зазвичай відбувається через `await`:

```swift
actor Counter {
    private var value = 0

    func increment() {
        value += 1
    }

    func currentValue() -> Int {
        value
    }
}

let counter = Counter()
Task {
    await counter.increment()
    print(await counter.currentValue())
}
```

Тут `Counter` сам володіє своїм станом. Зовнішній код не змінює `value` напряму, а просить actor виконати метод. Це зменшує ризик **гонки даних** — ситуації, коли кілька задач одночасно читають і змінюють те саме значення, а результат залежить від випадкового порядку виконання.

Не плутай асинхронність із паралельністю: `async/await` описує роботу з операціями, що можуть призупинятися; фактичне планування залежить від runtime та executor. `Task` не є гарантією, що код виконається на окремому потоці.

## Як думати над задачею

Перед написанням коду постав собі чотири питання:

1. **Хто володіє об'єктом?** Сильне посилання має бути у того, хто відповідає за його життя.
2. **Чи може власник зникнути раніше?** Якщо так, зв'язок-спостерігач або делегат часто має бути `weak`.
3. **Де програма чекає?** Познач функцію `async`, а місце отримання результату — `await`; не додавай `Task` лише «для швидкості».
4. **Хто змінює спільні дані?** Збери змінний стан в одному `actor` і надай короткі методи для безпечної роботи з ним.

Windows / PowerShell:



Скрипти додають `-parse-as-library`, потрібний для прикладу з `@main`. ARC, `async/await` і `actor` — частина Swift і доступні для вивчення на Windows та Linux.

Якщо ти працюєш у Xcode, кнопка **Run** (трикутник ▶) збирає проєкт і запускає його. Червона кнопка **Stop** (квадрат ■) зупиняє запущену програму. Панель **Console** внизу показує `print` і повідомлення про помилки. У SwiftUI зміни інтерфейсу краще робити в головному контексті, а довгі операції — виконувати асинхронно, щоб вікно не «зависало».

## Практичне завдання

Створи невеликий приклад лічильника і перевір його поступово:

1. Створи `actor Counter` із приватним цілим значенням `value = 0`.
2. Додай метод `increment()`, який збільшує значення на один.
3. Додай метод читання поточного значення.
4. Створи екземпляр `Counter` і дві `Task`, кожна з яких кілька разів викликає `await counter.increment()`.
5. Прочитай значення після завершення задач і порівняй його з очікуваним результатом.
6. Додай короткий `Task.sleep(nanoseconds: 100_000_000)` лише в асинхронний код, якщо хочеш змоделювати очікування. Для `try await` оброби можливу помилку через `do`/`catch` або `try?`.
7. Окремо зміни приклад із `Person` та `Apartment`: заміни `weak` на сильне посилання, перевір, що `deinit` більше не виконується, і поясни чому. Потім поверни `weak`.

## Типові помилки

- **Замінити `weak` на `unowned` «бо коротше».** Причина: життєвий цикл об'єкта насправді не доведений. Виправлення: використовуй `weak`, якщо посилання може стати недійсним.
- **Створити сильні посилання в обидва боки.** Причина: кожен об'єкт утримує іншого. Виправлення: зроби один напрямок слабким і перевір звільнення через `deinit`.
- **Викликати асинхронну функцію без `await`.** Причина: виклик не позначає точку очікування. Виправлення: виконуй його в `async`-контексті й додай `await`.
- **Вважати, що `Task` автоматично означає паралельний потік.** Причина: змішані поняття задачі, потоку й призупинення. Виправлення: думай про `Task` як про одиницю асинхронної роботи, а не про обіцянку окремого потоку.
- **Змінювати одну звичайну змінну з кількох задач.** Причина: виникає гонка даних. Виправлення: ізолюй стан в `actor` або спроєктуй власника стану так, щоб одночасна зміна була неможлива.
- **Додати `await` перед синхронною функцією.** Причина: `await` не пришвидшує звичайний код і потрібен для потенційно призупинюваного асинхронного виклику. Виправлення: позначай `async` лише там, де це відповідає операції.

## Перевір себе

Спробуй відповісти без підглядання:

1. Що саме рахує ARC і коли екземпляр класу звільняється?
2. Чим `weak` відрізняється від `unowned`?
3. Чому цикл сильних посилань може залишити об'єкт у пам'яті?
4. Що означають `async` та `await`, і чому `await` не обіцяє окремого потоку?
5. Навіщо `actor` потрібен лічильнику?
6. У якому місці твого прикладу може виникнути гонка даних без `actor`?

Ти готовий рухатися далі, якщо можеш намалювати напрямки сильних і слабких посилань, пояснити вибір `weak`, написати коротку `async` функцію з `await` і без помилки запустити метод `actor` з `Task`. Якщо програма поводиться незрозуміло, спочатку виведи стан через `print`, перевір місце `await` і знайди, хто саме володіє кожним об'єктом.
