# Урок 8. Підсумковий кросплатформний проєкт

## Проєкт: трекер навчання

Створи консольний застосунок, який допомагає вести список тем, що ти вивчаєш. Він має працювати на Windows, Linux і macOS без переписування основної логіки.

### Вимоги

- `StudyItem`: стабільний ID, назва, статус, дата створення.
- `StudyStatus`: `planned`, `inProgress`, `completed`.
- Додавання нового елемента.
- Зміна статусу.
- Перегляд усіх, активних і завершених елементів.
- Підрахунок завершених тем.
- Збереження та завантаження JSON.
- Тести для додавання, фільтрації, статусів і кодування.

## Послідовність

1. Спершу опиши типи.
2. Додай чисті функції для операцій зі списком.
3. Напиши тести на правила.
4. Додай JSON-сховище через Foundation.
5. Під'єднай просте консольне меню.
6. Перевір чисту збірку й тести на своїй ОС.

## Перевірка на різних операційних системах

Windows / PowerShell:

```powershell
swift build
swift test
swift run
```

Linux / macOS:

```bash
swift build
swift test
swift run
```

Твоя мета — щоб модель, правила, JSON і тести працювали без умов на кшталт `#if os(Windows)` або `#if os(Linux)`. Не додавай такі розгалуження, якщо немає реальної системної причини.

Для роботи з файлами не склеюй абсолютні шляхи рядками. Використовуй `URL` і `FileManager` з Foundation; приклад є в [довіднику платформ](../docs/PLATFORM-GUIDE.md).

## Після основного курсу

- **Windows або Linux:** продовжуй із CLI-інструментами, бібліотеками, серверною розробкою, системними утилітами та міжплатформними пакетами.
- **macOS:** додатково встанови Xcode, відкрий пакет у Xcode та створи окремий SwiftUI-проєкт.
- **Якщо згодом з'явиться Mac:** перенеси перевірену модель `StudyItem` у UI-проєкт; не змішуй бізнес-логіку з відображенням.

Основний курс завершується кросплатформним консольним застосунком. Mac — це можливість продовжити навчання розробкою для екосистеми Apple, а не умова для завершення курсу.
