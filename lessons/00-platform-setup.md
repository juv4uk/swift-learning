# Урок 0. Підготуй середовище Swift

Цей урок потрібен незалежно від операційної системи. **Не потрібно купувати Mac, щоб пройти основний курс Swift.** Уроки, приклади, Swift Package Manager і підсумковий консольний проєкт розраховані на Windows, Linux і macOS.

## Що ти вивчиш і навіщо

Після уроку ти зможеш:

- визначити, які інструменти потрібні саме для твоєї системи;
- перевірити, що командний рядок бачить Swift;
- завантажити навчальний репозиторій і запустити готовий приклад;
- відрізнити компіляцію, запуск і тестування;
- зрозуміти, коли потрібні `swiftc`, Swift Package Manager і, на macOS, Xcode.

**Середовище розробки** — це програми та налаштування, за допомогою яких ми пишемо й запускаємо код. **Toolchain (набір інструментів)** містить компілятор та інші команди Swift. **Компілятор** перетворює текст програми на виконуваний файл. **Термінал** — програма, у якій ми вводимо команди; PowerShell є терміналом Windows, а Bash часто використовується в Linux і macOS.

## 1. Обери свою систему

- **Windows 10/11 x64 або ARM64:** встанови Swift toolchain, Visual Studio 2022 Build Tools із C++ toolchain та Windows SDK. Увімкни Developer Mode, як вимагає офіційна інструкція.
- **Linux:** використовуй підтримуваний дистрибутив і Swiftly. Swift.org перелічує Ubuntu 22.04+, Debian 12+, Fedora 41+, Amazon Linux 2023 та Red Hat Universal Base Image 9. Підтримувані архітектури й точні версії залежать від релізу.
- **macOS:** встанови Xcode або Command Line Tools. Цей напрям також дозволяє пізніше перейти до SwiftUI.

Детальні інструкції:

- [Swift на Windows](../docs/SETUP-WINDOWS.md)
- [Swift на Linux](../docs/SETUP-LINUX.md)
- [Swift на macOS](../docs/SETUP-MACOS.md)
- [Актуальна підтримка платформ на Swift.org](https://www.swift.org/platform-support/)

### Що саме встановлюється на macOS

**Command Line Tools** дають терміналу компілятор Swift та базові інструменти. **Xcode** — повніше середовище Apple: у ньому можна створювати проєкти, редагувати файли, запускати програму кнопкою **Run** (трикутник ▶), зупиняти її кнопкою **Stop** (квадрат ■) і дивитися помилки внизу в області звіту. Xcode не потрібен для основного консольного курсу, але стане потрібним для багатьох застосунків під Apple-платформи.

**SwiftUI** — фреймворк для побудови інтерфейсу з опису екрана у Swift. Це не окрема мова і не заміна компілятору: SwiftUI використовує Swift та інструменти Xcode. У цьому уроці ми лише готуємо середовище; створення екранів буде окремою темою.

## 2. Перевір, що компілятор доступний

Відкрий новий термінал після встановлення. Нове вікно важливе: воно перечитує налаштування `PATH` — список папок, де система шукає команди.

У PowerShell:

```powershell
swift --version
swiftc --version
swift package --version
```

У Bash (Linux або macOS):

```bash
swift --version
swiftc --version
swift package --version
```

Команда `swift` — загальний інструмент Swift, `swiftc` — компілятор, а `swift package` — команда для роботи з пакетами. Параметр `--version` просить програму лише надрукувати версію, тому він нічого не змінює у твоєму проєкті.

Для цього курсу використовуй стабільний Swift 6.4.2 або сумісний новіший стабільний реліз. Не використовуй development snapshot як основний навчальний toolchain.

Якщо бачиш повідомлення на кшталт «команду не знайдено», не переходь далі навмання: повернися до інструкції для своєї системи, перевір встановлення toolchain і відкрий термінал ще раз.

## 3. Отримай навчальний репозиторій

**Репозиторій** — папка з файлами проєкту та історією змін Git. Команда `git clone` створює на твоєму комп’ютері копію репозиторію з GitHub.

PowerShell:

```powershell
git clone https://github.com/juv4uk/swift-learning.git
Set-Location .\swift-learning
```

Bash:

```bash
git clone https://github.com/juv4uk/swift-learning.git
cd swift-learning
```

`Set-Location` і `cd` роблять одне й те саме: переходять до іншої папки. Після цих команд ти маєш перебувати всередині папки `swift-learning`. Перевір це командою `pwd` у Bash або PowerShell; вона покаже поточний шлях.

## 4. Запусти перший приклад

Windows / PowerShell:

```powershell
.\scripts\run-example.ps1 01-hello
```

Linux / macOS:

```bash
./scripts/run-example.sh 01-hello
```

Частина `01-hello` — назва прикладу, а шлях `./scripts/...` означає «скрипт у папці `scripts` поточного проєкту». Скрипт автоматизує повторювані дії: знаходить потрібний файл, компілює його та запускає.

Якщо PowerShell блокує запуск локального навчального скрипту політикою виконання, тимчасово дозволь скрипти лише в поточному вікні:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

`-Scope Process` означає, що зміна діє тільки до закриття цього вікна PowerShell. Це не змінює політику назавжди. Після цього повтори команду запуску прикладу.

Альтернатива — компілюй файл без скрипту через `swiftc`. У Windows програма матиме суфікс `.exe`; у Linux/macOS — зазвичай без суфікса.

### Перший короткий приклад без скрипту

Створи файл `Hello.swift` у будь-якій тимчасовій папці та запиши в нього:

```swift
print("Привіт, Swift!")
```

У цій програмі `print` виводить текст, дужки містять аргумент для виведення, а текст у подвійних лапках є рядком. Запусти файл так:

Bash:

```bash
swiftc Hello.swift -o hello
./hello
```

PowerShell:

```powershell
swiftc Hello.swift -o hello.exe
.\hello.exe
```

Розбір команд:

1. `swiftc Hello.swift` передає файл компілятору.
2. `-o hello` або `-o hello.exe` задає ім’я результату.
3. Окрема команда запускає вже скомпільовану програму.
4. На екрані має з’явитися `Привіт, Swift!`.

Це допомагає розділити дві дії: **скомпілювати** код і **запустити** результат. Якщо змінити текст у файлі, потрібно знову виконати `swiftc`, а потім запуск.

## 5. Перевір Swift Package Manager

**Swift Package Manager (SPM)** — інструмент Swift для опису, збирання і тестування пакетів. Пакет — це організований проєкт із кодом, налаштуваннями та, за потреби, залежностями.

Команди однакові в PowerShell і Bash:

```text
swift build
swift run
swift test
```

- `swift build` компілює пакет, але не обов’язково запускає програму.
- `swift run` збирає пакет за потреби та запускає його виконувану програму.
- `swift test` запускає автоматичні тести — маленькі перевірки, які показують, чи працює код очікувано.

Запускай ці команди з кореня репозиторію, де є файл опису пакета. Якщо термінал повідомляє, що пакет не знайдено, спочатку перевір поточну папку.

## 6. Як думати над задачею

Коли щось не працює, не змінюй одразу багато налаштувань. Рухайся від простого до складного:

1. **Де я перебуваю?** Перевір поточну папку та назву команди.
2. **Чи бачить система інструмент?** Виконай `swift --version`.
3. **Чи правильно написана команда?** Порівняй оболонку: у PowerShell шлях має `\.`, у Bash — `./`.
4. **На якому кроці сталася помилка?** Розділи компіляцію, запуск і тестування.
5. **Що буквально каже повідомлення?** Спочатку виправ перший рядок помилки, потім повтори команду.

Такий порядок економить час: помилка `swift: command not found` не виправляється зміною коду, бо проблема виникла ще до компіляції.

## 7. Зрозумій одну важливу відмінність

На Linux та macOS можна використовувати інтерактивний Swift REPL там, де його підтримує встановлений toolchain. На Windows інтерактивний REPL не підтримується. Це не обмежує проходження курсу: використовуй `swiftc`, `swift run` і `swift test`.

Сам Swift-код уроків спільний. Відрізняються команди оболонки, розширення виконуваного файлу та системні інструменти.

## 8. Практичне завдання

Виконай кроки послідовно:

1. Встанови інструменти за інструкцією для Windows, Linux або macOS.
2. Відкрий новий термінал і виконай усі три команди версії.
3. Клонуй репозиторій та перейди в його папку.
4. Запусти приклад `01-hello` відповідним скриптом.
5. Запусти `swift build`, потім `swift run`, потім `swift test`.
6. Створи тимчасовий `Hello.swift`, скомпілюй його через `swiftc` і перевір рядок `Привіт, Swift!`.
7. За бажанням відкрий проєкт у Xcode на macOS: знайди кнопку **Run**, запусти консольну програму та переглянь її вивід у нижній області.

## Типові помилки

| Повідомлення або ситуація | Причина | Виправлення |
|---|---|---|
| `swift` або `swiftc` не знайдено | toolchain не встановлено або старий термінал не бачить `PATH` | перевір інструкцію своєї системи, відкрий новий термінал і повтори перевірку версії |
| `No such file or directory` / шлях не знайдено | команда запущена не з кореня репозиторію або переплутано `./` і `.\` | виконай `cd` або `Set-Location` до `swift-learning` і використай команду для своєї оболонки |
| PowerShell не запускає `.ps1` | діє політика виконання скриптів | застосуй `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`, потім повтори запуск |
| `swift test` не працює в довільній папці | у поточній папці немає Swift-пакета | перейди до папки, де розташований пакет і його опис |
| після зміни `Hello.swift` вивід старий | програма не була перекомпільована | знову виконай `swiftc`, а потім запусти створений файл |
| на Windows шукаєш REPL | інтерактивний REPL там не підтримується | використовуй файл, `swiftc`, `swift run` і `swift test` |

## Перевір себе

Відповідай без підглядання:

1. Чим відрізняються `swiftc` і `swift run`?
2. Навіщо відкривати новий термінал після встановлення toolchain?
3. Чому `./scripts/run-example.sh` і `.\scripts\run-example.ps1` мають різний запис?
4. Що перевіряє `swift test`?
5. Що робить параметр `-o` у команді `swiftc`?
6. Чим Xcode відрізняється від самого Swift toolchain?

Ти готовий до уроку 1, якщо всі три команди версії працюють, приклад `01-hello` запускається, `swift build` і `swift test` завершуються успішно, а ти можеш своїми словами пояснити різницю між компіляцією та запуском. Якщо щось не вдалося, це не провал: повернися до відповідного розділу, прочитай перше повідомлення помилки й повтори лише потрібний крок.

## Контрольна точка

Переходь до уроку 1, коли всі три команди версії працюють, приклад `01-hello` запускається, а `swift build` і `swift test` завершуються успішно.
