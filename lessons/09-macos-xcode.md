# Урок 9. macOS та Xcode

## Мета

Навчитися користуватися Mac як робочим середовищем і самостійно створити перший проєкт у Xcode.

## Що ти вивчиш і навіщо

Після уроку ти зможеш:

- орієнтуватися у Finder і Terminal та розуміти, де знаходяться файли;
- перевірити, чи підходять твій Mac, macOS і Xcode для навчання;
- створити простий macOS-застосунок на SwiftUI;
- розрізняти **проєкт**, **target** і **scheme** в Xcode;
- запустити застосунок, переглянути повідомлення в консолі та зупинити програму на breakpoint.

Це важливо, бо Xcode — не лише редактор коду. Він також збирає програму, запускає її, показує помилки й допомагає досліджувати виконання коду.

## План

1. Ознайомся з Finder, домашньою текою, шляхами, розширеннями та системними дозволами.
2. Відкрий Terminal. Відпрацюй `pwd`, `ls`, `cd`, `mkdir`, `open`, `git status`.
3. Перевір сумісність моделі Mac, macOS і стабільного Xcode за офіційною таблицею Apple.
4. Встанови Xcode, відкрий його та дочекайся додаткових компонентів.
5. Створи macOS App із SwiftUI, запусти на Mac, досліди Project Navigator, target, scheme, build settings, Preview та Simulator.
6. Постав breakpoint, переглянь значення змінних, console та call stack.

## 1. macOS: де знаходяться файли

**Finder** — програма для перегляду файлів і тек. У лівій панелі Finder зазвичай є домашня тека, Downloads і Documents. Твоя **домашня тека** — особистий каталог користувача. У шляхах її часто позначають символом `~`.

**Шлях** описує, як дістатися до файлу. Наприклад, `~/Documents/Swift/` означає теку `Swift` усередині `Documents` у твоїй домашній теці. Розширення після крапки, наприклад `.swift` або `.md`, підказує тип файлу, але саме по собі не змінює його вміст.

macOS може попросити дозвіл на доступ до Desktop, Documents, Downloads або зовнішнього диска. Це не помилка Xcode: система захищає особисті файли. Якщо довіряєш програмі, переглянь запит і надай лише потрібний дозвіл у **System Settings → Privacy & Security**. Не вимикай захист навмання.

### Terminal і базові команди

**Terminal** — текстовий спосіб керувати файлами та запускати команди. Відкрий його через Spotlight: натисни `Command + Space`, введи `Terminal` і натисни `Return`.

Виконуй команди по одній. Після команди натискай `Return` і дивись на результат:

```bash
pwd
ls
cd ~/Documents
mkdir SwiftPractice
cd SwiftPractice
open .
git status
```

Що робить кожна команда:

- `pwd` (**print working directory**) показує теку, у якій ти зараз перебуваєш;
- `ls` показує вміст поточної теки;
- `cd` (**change directory**) переходить до іншої теки;
- `mkdir` створює теку;
- `open .` відкриває поточну теку у Finder; крапка означає «поточна тека»;
- `git status` показує стан Git-репозиторію. Якщо ти не в репозиторії, Git повідомить про це — це очікувано.

Пробіли в шляхах можуть ускладнити команду. Надійний спосіб — почати вводити шлях і перетягнути теку з Finder у Terminal: macOS вставить правильний шлях.

## 2. Перевірка та встановлення Xcode

Перед встановленням перевір модель Mac і версію macOS: меню **Apple  → About This Mac**. Потім відкрий офіційну сторінку системних вимог Xcode з розділу «Матеріали» нижче. Вона потрібна, бо сумісність залежить від конкретної версії Xcode і macOS; не орієнтуйся на випадкові старі інструкції.

Встановити Xcode можна з Mac App Store або з офіційного сайту Apple, якщо це відповідає твоєму курсу чи організації. Після першого запуску Xcode може попросити прийняти умови та встановити додаткові компоненти. Дочекайся завершення: переривання цього кроку може призвести до помилок під час збірки.

У Xcode ти часто працюватимеш із такими елементами:

- **Project Navigator** (іконка папки зліва) — список файлів проєкту; тут відкривають `ContentView.swift` та інші файли.
- **Editor** (центральна частина) — місце для читання й редагування коду.
- **Inspector** (права панель) — властивості вибраного файлу, подання або налаштування.
- **Run** (кнопка з трикутником ▶) — зібрати та запустити вибрану схему.
- **Stop** (кнопка з квадратом ■) — зупинити запущений застосунок.
- **Scheme** (назва застосунку поруч із кнопкою Run) — що саме запускати і на якому призначенні, наприклад на цьому Mac.
- **Build** — перетворення Swift-коду та ресурсів на програму. Помилка build означає, що Xcode не зміг створити працездатний результат.

### Створення першого проєкту

1. Запусти Xcode і вибери **Create a new Xcode project**.
2. Обери шаблон **macOS → App** і натисни **Next**. Шаблон створює початкову структуру, щоб не налаштовувати все вручну.
3. У полі **Product Name** введи `StudyTracker`.
4. Вибери **Interface: SwiftUI**, **Language: Swift**. Якщо Xcode показує додаткові поля, залишай їх типовими, якщо в курсі не сказано інакше.
5. Збережи проєкт у зрозумілій теці. Прапорець Git можна залишити увімкненим, якщо хочеш одразу мати локальний репозиторій.
6. Натисни **Create**. У Project Navigator відкрий файл `ContentView.swift`.

Поруч із кнопкою Run вибери призначення для Mac. **Simulator** — це віртуальний пристрій Apple для тестування застосунків, переважно iPhone або iPad. Для цього уроку запускай macOS App на **My Mac**; Simulator не замінює запуск macOS-програми на самому Mac.

## 3. Перший SwiftUI-приклад

Замініть вміст `ContentView.swift` на такий код (якщо Xcode згенерував `#Preview`, його можна замінити цим варіантом):

```swift
import SwiftUI

struct ContentView: View {
    @State private var message = "Ще не виконано"

    var body: some View {
        VStack(spacing: 12) {
            Text("StudyTracker")
                .font(.title)

            Text("Маленький крок у навчанні Swift")

            Text(message)

            Button("Позначити виконаним") {
                message = "Виконано!"
                print("Користувач натиснув кнопку")
            }
        }
        .padding()
    }
}

#Preview {
    ContentView()
}
```

### Терміни та покроковий розбір

- `import SwiftUI` підключає фреймворк із готовими типами для побудови інтерфейсу.
- `struct ContentView: View` оголошує структуру `ContentView`, яка відповідає протоколу `View`. Тобто її можна показати як частину інтерфейсу.
- `@State private var message` — локальний стан цього подання. Коли значення змінюється, SwiftUI оновлює місця, де використовується `message`.
- `var body: some View` описує, що має бути на екрані. `some View` означає, що результат є певним типом подання, але нам не потрібно називати його складний конкретний тип.
- `VStack` розміщує елементи вертикально, а `spacing: 12` задає проміжок між ними.
- `Text` показує напис, `.font(.title)` застосовує стиль заголовка, а `.padding()` додає внутрішній відступ навколо всієї групи.
- `Button` має назву та замикання — код у фігурних дужках, який виконається після натискання.
- `message = "Виконано!"` змінює стан. `print(...)` виводить рядок у консоль Xcode, але не в інтерфейс застосунку.
- `#Preview` просить Xcode показати `ContentView` у canvas Preview. Preview зручний для швидкого перегляду, але запуск через Run перевіряє реальний процес програми.

Щоб перевірити код, натисни **Resume** або кнопку ▶ у Preview, якщо Xcode пропонує такий запуск. Потім натисни ▶ **Run**. У вікні застосунку натисни кнопку й переконайся, що текст змінився. Для консолі відкрий область налагодження внизу Xcode та натисни кнопку ще раз: там має з’явитися повідомлення з `print`.

## 4. Як думати над задачею

Не починай із пошуку складних компонентів. Спочатку розклади вимогу на три питання:

1. **Що бачить користувач?** Тут це заголовок, опис, поточний стан і кнопка.
2. **Що може змінюватися?** Повідомлення змінюється після натискання, тому для нього потрібен `@State`.
3. **Яка подія змінює стан?** Замикання `Button` присвоює новий текст.

Таке розкладання допомагає відрізнити дані від інтерфейсу: `message` — дані, а `Text(message)` — їхнє відображення.

## 5. Project, target, scheme і налагодження

Ці терміни схожі, але означають різне:

- **Project** — контейнер із файлами, ресурсами та загальними налаштуваннями розробки.
- **Target** — конкретний результат, який можна зібрати, наприклад macOS-застосунок `StudyTracker`. У нього є власні налаштування збірки та список файлів.
- **Scheme** — набір вказівок для Xcode: який target зібрати, у якому режимі та де запустити. Тому зміна scheme може змінити призначення запуску, не змінюючи код.
- **Build Settings** — детальні параметри компілятора, підпису, мінімальної версії системи та інших етапів збірки. Не змінюй їх навмання: спочатку прочитай назву й причину зміни.

Постав breakpoint: відкрий рядок `message = "Виконано!"` і клацни по полю з номером рядка зліва. З’явиться синя позначка. Запусти застосунок і натисни кнопку. Xcode призупинить виконання перед цим рядком.

Поки програма зупинена:

- у **Variables View** переглянь поточне значення `message`;
- у **console** внизу прочитай вивід `print` (він з’явиться після виконання рядка; для цього натисни кнопку продовження ▶);
- у **call stack** подивись ланцюжок викликів, який привів програму до breakpoint.

Кнопка **Continue** (трикутник) продовжує виконання, **Step Over** переходить до наступного рядка без заходу всередину виклику, а **Stop** завершує запуск. Breakpoint не є помилкою: це навмисна зупинка для дослідження програми.

## Практичне завдання

Створи застосунок `StudyTracker` із заголовком, коротким описом і кнопкою. Зміни текст кнопки після натискання. Збери та запусти застосунок.

Послідовність виконання:

1. Перевір сумісність Mac і Xcode за офіційною таблицею Apple.
2. Створи проєкт macOS App з інтерфейсом SwiftUI та мовою Swift.
3. Додай заголовок, опис і стан повідомлення через `@State`.
4. Додай `Button`, який змінює стан після натискання.
5. Запусти Preview, а потім повний застосунок через Run на **My Mac**.
6. Перевір повідомлення `print` у консолі.
7. Постав breakpoint на присвоєння нового повідомлення, натисни кнопку та прочитай значення змінної.
8. Зафіксуй версії macOS, Xcode та Swift у коментарі до Issue.

## Типові помилки

- **`git status` показує, що це не репозиторій.** Команду виконано не в теці проєкту або Git ще не налаштовано. Перевір `pwd` і перейди через `cd` у правильну теку.
- **Немає кнопки Run або запуск не відбувається.** Не вибрано схему чи призначення. Обери target `StudyTracker` і **My Mac** у верхній панелі.
- **Preview не оновлюється.** У коді може бути синтаксична помилка або Preview призупинено. Прочитай першу помилку в Issue navigator, виправ її, а потім натисни Resume.
- **Застосунок збирається, але кнопка нічого не змінює.** Перевір, що змінна оголошена з `@State`, а `Text` використовує саме `message`, не старий літерал.
- **Не видно `print`.** Консоль показує вивід Xcode, а не текст у вікні застосунку. Відкрий Debug area внизу і натисни кнопку після запуску.
- **Breakpoint не спрацьовує.** Переконайся, що він стоїть на рядку, який справді виконується, і що ти запускаєш застосунок через Run, а не лише дивишся статичний Preview.
- **macOS просить доступ до файлів.** Це системний дозвіл. Перевір шлях і надай доступ лише до потрібної теки, не обходь попередження випадковими командами.

## Перевір себе

Відповідай без підглядання:

1. Що покаже `pwd`, а що — `ls`?
2. Чим відрізняються Project, target і scheme?
3. Навіщо потрібні `@State` і `Button` у прикладі?
4. Чим Preview відрізняється від запуску через Run на My Mac?
5. Де шукати результат `print` і як дізнатися значення змінної на breakpoint?
6. Чому зміна `message` оновлює текст у `Text(message)`?

Ти готовий рухатися далі, якщо можеш самостійно створити й запустити `StudyTracker`, пояснити призначення основних панелей Xcode, змінити текст після натискання, знайти повідомлення в консолі та прочитати значення змінної на breakpoint. Також перевір усі пункти нижнього чекліста.
