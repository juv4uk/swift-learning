# Урок 11. Архітектура, SwiftData та асинхронні дані

## Мета
З'єднати інтерфейс із моделлю та постійним сховищем, не перетворюючи SwiftUI View на місце для всієї логіки.

## Теми
- Розділення моделі, бізнес-правил, зберігання та відображення.
- SwiftData: модель, `ModelContainer`, контекст, запити, вставлення, редагування й видалення.
- Стан завантаження, порожній стан, помилка.
- `Task`, `async/await`, скасування задач у життєвому циклі UI.
- `URLSession`, HTTP, `Codable`, обробка статус-кодів і помилок мережі.

## Практичне завдання
1. Перенеси модель StudyItem із кросплатформного проєкту в Apple App target або окремий спільний модуль.
2. Під'єднай SwiftData й перевір, що записи переживають перезапуск.
3. Додай асинхронне завантаження демонстраційних даних із відкритого API.
4. Покажи loading, success, empty та error стани.
5. Переконайся, що відсутність мережі не ламає локальний трекер.

Не додавай приватні ключі або секрети до репозиторію. Не роби мережевий запит без обробки помилки та скасування.

## Критерії готовності
- [ ] Бізнес-правила не залежать від SwiftUI View.
- [ ] Записи зберігаються після закриття й повторного запуску.
- [ ] Є зрозумілий стан помилки та порожнього списку.
- [ ] Асинхронна операція не блокує інтерфейс.
- [ ] Можу пояснити, де знаходиться джерело істини для даних.
