# Урок 7. Пакети, тести та JSON

## Що ти вивчиш і навіщо

У цьому уроці ти побачиш, як Swift-проєкт організований у пакет, як запускати його з командного рядка, як перевіряти код тестами та як обмінюватися даними у форматі JSON.

Це важливо, бо реальна програма рідко складається з одного файлу. Вона має окремі модулі, залежності, автоматичні перевірки та дані, які приходять із файлу або мережі. Після уроку ти зможеш:

- пояснити, навіщо потрібен `Package.swift`;
- розрізняти модуль, ціль (target) і продукт;
- закодувати Swift-значення в JSON і декодувати JSON назад;
- написати тест на успішний сценарій і на помилкові дані;
- запускати збірку, програму й тести командами Swift Package Manager.

## Swift Package Manager

**Swift Package Manager (SPM)** — інструмент Swift для створення, збирання та тестування пакетів. Пакет — це папка з описом проєкту та його початковим кодом. Головний файл опису — `Package.swift`.

`Package.swift` описує пакет: продукти, цілі, залежності та платформи. **Ціль** (target) — окрема частина коду, яку Swift збирає разом: наприклад, бібліотека, виконувана програма або тести. **Продукт** (product) — те, що пакет надає назовні, наприклад бібліотека для підключення до іншого пакета.

Основні команди:

```bash
swift build
swift run
swift test
```

Що робить кожна команда:

- `swift build` компілює код, але не запускає програму. Так можна швидко перевірити, чи немає помилок компіляції.
- `swift run` спочатку збирає пакет, а потім запускає його виконувану ціль. Якщо є кілька виконуваних цілей, може знадобитися вказати її назву.
- `swift test` збирає тестову ціль і запускає тести. Саме цю команду варто виконувати після змін у логіці.

Запускай команди з кореня пакета — з папки, де лежить `Package.swift`. Якщо термінал повідомляє, що такого файлу не знайдено, спочатку перевір поточну папку командою `pwd` (macOS/Linux) або `Get-Location` (PowerShell).

### Як це виглядає в Xcode

Xcode — графічне середовище для Swift і Apple-платформ. Коли ти відкриваєш пакет у Xcode, зліва **Project navigator** показує файли, а кнопка з трикутником **Run** збирає та запускає виконувану програму. Кнопка з ромбом або команда **Test** запускає тести. Повідомлення про помилки з’являються внизу у звіті: натисни на помилку, щоб перейти до відповідного рядка.

Для цього уроку Xcode не обов’язковий: ті самі дії можна виконувати командами `swift build`, `swift run` і `swift test` у Terminal. Не плутай кнопку **Run** із **Test**: перша запускає програму, друга запускає перевірки.

## Модулі та доступ

**Модуль** — набір коду, який можна підключити одним ім’ям. `import` підключає модуль, наприклад:

```swift
import Foundation
```

`public` відкриває API для інших модулів; без модифікатора оголошення зазвичай доступне лише в межах модуля (`internal`). **API** — це частина коду, якою можуть користуватися інші частини програми. Не відкривай усе без потреби: що менше публічних деталей, то легше змінювати внутрішню реалізацію.

Уяви бібліотеку `StudyKit`. Її користувачеві може бути потрібна функція `public`, а допоміжна змінна або алгоритм можуть залишитися `internal`. Тест тієї самої цілі часто імпортує код через `@testable import`, щоб перевірити внутрішні оголошення під час тестування. Назва після `import` має відповідати назві модуля з твого пакета.

## Codable і JSON

**JSON** — текстовий формат для обміну структурованими даними. Об’єкт JSON записують у фігурних дужках, ключі — рядками, а масив — у квадратних дужках. Наприклад:

```json
{"title":"Повторити Codable","done":false}
```

`Codable` — псевдонім для двох протоколів: `Encodable` (можна закодувати) і `Decodable` (можна декодувати). Типи, що відповідають `Codable`, можна кодувати й декодувати, наприклад у JSON. `JSONEncoder` перетворює Swift-значення на `Data`, а `JSONDecoder` перетворює `Data` назад на Swift-значення.

Ось повний короткий приклад, який можна скомпілювати у файлі Swift-пакета з доступним `Foundation`:

```swift
import Foundation

struct StudyItem: Codable, Equatable {
    let title: String
    let done: Bool
}

let original = StudyItem(title: "Повторити Codable", done: false)
let encoder = JSONEncoder()
let decoder = JSONDecoder()

let data = try encoder.encode(original)
let decoded = try decoder.decode(StudyItem.self, from: data)

print(decoded == original) // true
```

### Покроковий розбір

1. `struct StudyItem` описує власний тип даних із двома властивостями.
2. `Codable` додає можливість кодувати й декодувати значення. `Equatable` дозволяє порівняти два `StudyItem` у тесті.
3. `JSONEncoder` створює JSON-дані. Тип `Data` — це байти, а не обов’язково вже готовий для читання рядок.
4. `JSONDecoder` отримує `Data` і знає, що результат має бути `StudyItem.self`.
5. Якщо JSON має неправильну структуру або неправильний тип значення, `decode` кидає помилку. Тому дані ззовні потрібно вважати ненадійними: декодування може завершитися помилкою.

У функції або тесті зручніше обробляти помилку через `do`/`catch`:

```swift
 do {
    let item = try JSONDecoder().decode(StudyItem.self, from: data)
    print(item.title)
} catch {
    print("Не вдалося прочитати JSON: \(error)")
}
```

Не додавай `try!`, якщо дані можуть бути пошкоджені або прийшли від користувача: при помилці `try!` аварійно завершить програму.

## Тестування

Тест має перевіряти поведінку, а не внутрішню реалізацію. Наприклад, тестуй, що після round-trip (кодування, а потім декодування) значення не змінилося, а не те, яким саме способом працює `JSONEncoder`.

Назва тесту описує сценарій, assertion — очікуваний результат. У Swift-пакеті тестова ціль зазвичай містить `import XCTest` і `@testable import НазваМодуля`. Приклад тестів для `StudyItem`:

```swift
import XCTest
@testable import StudyKit

final class StudyItemTests: XCTestCase {
    func testJSONRoundTripPreservesValues() throws {
        let original = StudyItem(title: "Повторити Codable", done: false)
        let data = try JSONEncoder().encode(original)
        let decoded = try JSONDecoder().decode(StudyItem.self, from: data)

        XCTAssertEqual(decoded, original)
    }

    func testInvalidJSONThrows() {
        let invalidJSON = Data("{\"title\":42}".utf8)

        XCTAssertThrowsError(
            try JSONDecoder().decode(StudyItem.self, from: invalidJSON)
        )
    }
}
```

Заміни `StudyKit` на фактичну назву модуля у своєму пакеті. `XCTAssertEqual` перевіряє очікувану рівність, а `XCTAssertThrowsError` перевіряє, що операція справді завершується помилкою. `throws` у першому тесті дозволяє передати помилку XCTest без великого `do`/`catch`; якщо кодування або декодування не вдасться, тест завершиться невдало й покаже місце проблеми.

Якщо тест падає, читай не лише червоний статус, а й повідомлення: воно підказує, яке значення очікувалося та яке отримано. Один тест краще присвячувати одному сценарію, щоб причина помилки була зрозумілою.

## Як думати над задачею

Перед написанням коду постав собі чотири запитання:

1. **Яка модель даних?** Запиши властивості та їхні типи. Наприклад, `title` — `String`, `done` — `Bool`.
2. **Які дані входять?** Для JSON це можуть бути коректні дані або рядок із відсутнім ключем чи неправильним типом.
3. **Який результат вважається правильним?** Після round-trip значення мають бути рівні початковим.
4. **Що може піти не так?** Перевір декодування пошкодженого JSON окремим тестом.

Спочатку зроби найменший приклад, який компілюється. Потім додай один тест на нормальний сценарій і один на помилку. Так легше відрізнити помилку в моделі від помилки в тесті.

## Практичне завдання: `StudyItem`

Виконай кроки послідовно:

1. Створи або відкрий Swift-пакет і переконайся, що ти працюєш у папці з `Package.swift`.
2. Додай тип `StudyItem` із `Codable` та властивостями, які хочеш зберігати. Для порівняння в тесті додай також `Equatable`.
3. Створи значення `StudyItem`, закодуй його через `JSONEncoder` і декодуй назад через `JSONDecoder`.
4. Виведи декодоване значення або його `title`, щоб побачити результат.
5. Додай тест, що перевіряє збереження значень після round-trip.
6. Додай тест на некоректний JSON. Переконайся, що він перевіряє помилку, а не випадковий результат.
7. Запусти `swift build`, потім `swift test` і переконайся, що бачиш зрозумілий результат. Якщо в пакеті є виконувана ціль, за потреби запусти її через `swift run`.

## Типові помилки

- **Команда запускається не з тієї папки.** Причина: Swift не бачить `Package.swift`. Виправлення: перейди до кореня пакета й повтори команду.
- **`No such module` у тесті.** Причина: назва в `@testable import` не збігається з назвою модуля або ціль не додана до тестової залежності. Виправлення: перевір назви в `Package.swift` і заміни імпорт на фактичний.
- **Декодування падає на ключі або типі.** Причина: JSON не відповідає властивостям `Codable` — наприклад, число передано там, де очікується рядок. Виправлення: перевір JSON і модель; помилковий JSON залиш у тесті, який очікує помилку.
- **Очікування `true`, але отримано `false`.** Причина: після кодування або декодування змінилося значення чи тест порівнює не ті об’єкти. Виправлення: виведи `original` і `decoded`, а потім перевір кожну властивість.
- **Використано `try!` для зовнішніх даних.** Причина: примусове розпакування не обробляє помилку. Виправлення: у програмі використай `do`/`catch`, а в тесті — `throws` або `XCTAssertThrowsError`.
- **Тест перевіряє внутрішню реалізацію.** Причина: тест стає крихким і ламається після безпечного рефакторингу. Виправлення: перевіряй видиму поведінку та результат для конкретного сценарію.

## Команди на Windows і Linux

У PowerShell, Bash і macOS Terminal команди Swift Package Manager однакові:

```text
swift build
swift run
swift test
```

На Windows потрібні Developer Mode, Windows SDK та MSVC toolchain. На Linux перевір, що дистрибутив підтримується Swift.org. Інструкції: [Windows](../docs/SETUP-WINDOWS.md), [Linux](../docs/SETUP-LINUX.md).
