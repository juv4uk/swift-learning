# Урок 4. Протоколи, extensions і generics

## Мета

Описувати спільну поведінку без непотрібної ієрархії класів.

## Що ти вивчиш і навіщо

Після уроку ти зможеш:

- оголошувати протокол як список вимог до типу;
- додавати до типу зручні методи й обчислювані властивості через `extension`;
- писати generic-функції, які працюють із різними типами;
- читати обмеження на кшталт `T: Describable`;
- розділяти відповідальність: протокол описує можливість, а конкретний тип дає реалізацію.

Ці інструменти корисні, коли різні за змістом типи мають однакову поведінку. Наприклад, і `Book`, і `Course` можуть мати назву. Не обов'язково робити їх нащадками одного класу: достатньо домовитися про спільний протокол.

## Протокол

Протокол задає вимоги, які має виконати тип:

```swift
protocol Describable {
    var summary: String { get }
}
```

Це не готова властивість із текстом, а вимога: тип, який оголосить відповідність `Describable`, повинен мати доступну для читання властивість `summary` типу `String`. Позначка `{ get }` означає, що значення можна читати; протокол не вимагає, щоб його можна було змінювати.

Тип може відповідати кільком протоколам. Це дозволяє комбінувати можливості, не будуючи довгий ланцюжок успадкування.

## Перший повний приклад

```swift
protocol Describable {
    var summary: String { get }
}

struct Book: Describable {
    let title: String

    var summary: String {
        "Книга: \(title)"
    }
}

struct Course: Describable {
    let title: String

    var summary: String {
        "Курс: \(title)"
    }
}

func printSummary<T: Describable>(of value: T) {
    print(value.summary)
}

let book = Book(title: "Swift для початківців")
let course = Course(title: "Основи програмування")

printSummary(of: book)
printSummary(of: course)
```

### Покроковий розбір

1. `Describable` каже: «у мене має бути `summary`, яку можна прочитати».
2. `Book` і `Course` ставлять `: Describable`, тому кожен із них зобов'язаний надати цю властивість.
3. `summary` є обчислюваною властивістю: під час читання вона складає рядок із `title`.
4. `printSummary` приймає значення типу `T`, але тільки якщо `T` відповідає `Describable`.
5. Під час двох викликів Swift сам визначає, що `T` — це відповідно `Book` або `Course`.
6. Функції не потрібно знати всі можливі типи наперед. Їй достатньо знати, що в значення є `summary`.

`T: Describable` означає, що `T` має відповідати протоколу `Describable`. Якщо передати тип без `summary`, компілятор повідомить про помилку ще до запуску програми.

## Extension

`extension` додає обчислювані властивості або методи до наявного типу, не змінюючи його початкове оголошення.

Наприклад, основне оголошення `Book` може зберігати дані, а форматування для екрана можна винести окремо:

```swift
extension Book {
    var displayTitle: String {
        "📘 \(title)"
    }
}

print(book.displayTitle)
```

`extension` не створює новий тип і не змінює спосіб створення `Book`. Він лише додає можливість. Так код легше читати: властивості даних залишаються поруч із даними, а додаткові зручності — в окремому блоці.

У цьому прикладі `displayTitle` використовує вже наявне `title`. Оскільки `title` оголошено як `let`, extension не може змінити його, але може прочитати.

## Generics

Узагальнення, або generics, дозволяють писати функції для різних типів, якщо вони виконують спільну вимогу:

```swift
func printSummary<T: Describable>(of value: T) {
    print(value.summary)
}
```

Літера `T` — це тимчасове ім'я для конкретного типу. Під час виклику ним може стати `Book`, `Course` або інший тип, що відповідає `Describable`.

Без обмеження generic-функція не могла б безпечно звернутися до `value.summary`: невідомо, чи має довільний тип таку властивість. Обмеження `T: Describable` дає цю гарантію.

Generics не означають «ігнорувати типи». Навпаки, вони дозволяють один раз описати правило для багатьох типів і залишити перевірку типів компілятору.

## Як думати над задачею

Коли бачиш повторювану поведінку, рухайся в такому порядку:

1. **Назви спільну можливість.** Наприклад: «об'єкт можна показати як текст».
2. **Сформулюй мінімальну вимогу.** Якої властивості або методу достатньо? У прикладі — `summary`.
3. **Створи протокол.** Не додавай туди зайвих вимог, які потрібні лише одному типу.
4. **Змусь конкретні типи відповідати протоколу.** Нехай кожен сам визначить, як реалізувати вимогу.
5. **Винеси спільну операцію в generic-функцію.** Вона працює з вимогою, а не з конкретною назвою типу.
6. **Додай extension лише для зручностей.** Наприклад, форматування або маленький метод, який логічно належить типу.

Так ти спочатку моделюєш поведінку, а вже потім пишеш код. Це допомагає не створювати непотрібні базові класи.

## Практичне завдання: імена для різних типів

1. Створи протокол `IdentifiableByName` з властивістю `name` типу `String` і вимогою `{ get }`.
2. Створи `struct Book` із властивістю `name` та оголоси його відповідність `IdentifiableByName`.
3. Створи `struct Course` із такою самою вимогою.
4. Напиши generic-функцію, яка приймає будь-яке значення `T: IdentifiableByName` і друкує `value.name`.
5. Створи по одному `Book` і `Course`, передай їх у функцію та переконайся, що обидва імена виводяться.
6. Додай через `extension` обчислювану властивість, наприклад `displayName`, яка повертає рядок із префіксом `Книга:` або `Курс:`. Виведи її окремо.
7. Навмисно передай у generic-функцію тип без `name`, подивися на помилку компілятора, а потім прибери цей виклик або додай потрібну відповідність.

Роби кроки по одному. Після кожного кроку запускай код: так легше зрозуміти, чи проблема виникла в протоколі, відповідності типу, extension або generic-функції.

## Типові помилки

- **Властивість має не той тип.** Якщо протокол вимагає `var name: String { get }`, властивість `Int` не підходить. Виправлення: поверни саме `String`.
- **Тип не оголошено відповідним протоколу.** Наявність властивості сама по собі не додає формальної відповідності. Виправлення: напиши `struct Book: IdentifiableByName`.
- **Забуто реалізувати вимогу.** Запис `struct Book: IdentifiableByName` без `name` дасть помилку. Виправлення: додай властивість у тип або реалізуй її в extension.
- **Generic-функція не має обмеження.** У `func printName<T>(of value: T)` Swift не знає, що в `T` є `name`. Виправлення: напиши `func printName<T: IdentifiableByName>(of value: T)`.
- **Спроба змінити властивість із `{ get }`.** Така вимога гарантує читання, але не запис. Виправлення: якщо тип має зобов'язатися підтримувати запис, у протоколі потрібне `{ get set }`; якщо запис не потрібен, не змінюй значення.
- **Створення extension замість зміни типу.** Extension додає можливості, але не може додати збережену властивість із власним місцем у пам'яті. Виправлення: збережені дані оголошуй у `struct` або `class`, а в extension додавай обчислювані властивості чи методи.
- **Плутанина між протоколом і класом.** Протокол не створює об'єкт і не містить автоматично всю спільну реалізацію. Він описує договір. Виправлення: реалізацію дай в `struct`, `class` або extension.
