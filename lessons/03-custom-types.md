# Урок 3. Власні типи: struct, class, enum

## Мета

Навчитися описувати предметну область власними типами.

## Що ти вивчиш і навіщо

Після цього уроку ти зможеш:

- об'єднувати пов'язані дані й дії у `struct`;
- описувати невеликий, наперед відомий набір варіантів через `enum`;
- розрізняти копіювання значень (`struct`) і спільне посилання на об'єкт (`class`);
- читати `switch` з усіма варіантами перелічення;
- спроєктувати просту модель, наприклад книгу або профіль читача.

Це потрібно тому, що реальна програма працює не лише з окремими рядками й числами. Вона має поняття: користувач, книга, замовлення, статус. Власний тип дає такому поняттю зрозуміле ім'я та збирає його дані в одному місці.

## Перед першим прикладом: кілька термінів

- **Тип** — опис того, які дані може містити значення і що з ним можна робити. `String` та `Int` — стандартні типи Swift.
- **Екземпляр** — конкретне значення типу. Якщо `Programmer` — опис, то `Programmer(name: "Олена", experience: 3)` — один екземпляр.
- **Властивість** — дані всередині екземпляра, наприклад `name`.
- **Метод** — функція, оголошена всередині типу, наприклад `introduce()`.
- **Ініціалізатор** — код, який створює екземпляр. Для простої структури Swift часто створює такий ініціалізатор автоматично.

## `struct`

Структура групує пов'язані дані та поведінку. Зазвичай це добрий початковий вибір для моделі значення:

```swift
struct Programmer {
    let name: String
    var experience: Int

    func introduce() {
        print("Привіт! Я \(name).")
        print("Досвід: \(experience) років.")
    }
}

var developer = Programmer(name: "Олена", experience: 3)
developer.introduce()
developer.experience = 4
```

Покроково:

1. `struct Programmer` оголошує новий тип із назвою `Programmer`.
2. `let name` — обов'язкова властивість, яку не можна змінити після створення екземпляра.
3. `var experience` можна змінити, але лише якщо сам екземпляр оголошений через `var`.
4. `func introduce()` — поведінка програміста. Всередині методу `name` і `experience` означають властивості поточного екземпляра.
5. `Programmer(name: ..., experience: ...)` створює екземпляр. Для цих двох властивостей Swift надає memberwise initializer.
6. `developer.introduce()` викликає метод, а `developer.experience = 4` змінює досвід.

`let` у властивості означає, що її не можна змінити після створення екземпляра. `var` дозволяє змінювати властивість, якщо сам екземпляр оголошений через `var`.

### Значення копіюються

`struct` має **value semantics** — семантику значення. Після присвоєння дві змінні мають незалежні значення:

```swift
struct Score {
    var value: Int
}

var first = Score(value: 10)
var second = first
second.value = 20

print(first.value)  // 10
print(second.value) // 20
```

Рядок `var second = first` створює окреме значення. Тому зміна `second` не змінює `first`. Усередині Swift може оптимізувати копіювання, але спостережуваний результат залишається таким самим.

## `enum`

Перелічення описує скінченний набір станів. Воно підходить, коли значення має бути одним із чітко визначених варіантів:

```swift
enum StudyStatus {
    case planned, inProgress, completed
}

let status = StudyStatus.inProgress

switch status {
case .planned:
    print("Навчання ще не почалося")
case .inProgress:
    print("Навчання триває")
case .completed:
    print("Навчання завершено")
}
```

Тут `status` не є довільним рядком. Він може бути лише `.planned`, `.inProgress` або `.completed`. Крапка в `.inProgress` працює тому, що Swift уже знає тип змінної `status`.

`switch` має розглянути всі можливі варіанти `enum`. Це називається **повнотою** (`exhaustiveness`). Компілятор допоможе помітити, що ти забув додати гілку. Для навчального прикладу краще явно написати кожен `case`, а не приховувати помилки за `default`.

Назви `case` — це дані, а не текст для показу користувачу. Якщо треба вивести український опис, зроби це в гілках `switch`, як у прикладі.

## `class`

Клас також описує дані й поведінку, але має **reference semantics** — семантику посилання. Змінні можуть посилатися на той самий екземпляр. Ось короткий приклад:

```swift
class SharedScore {
    var value: Int

    init(value: Int) {
        self.value = value
    }
}

let first = SharedScore(value: 10)
let second = first
second.value = 20

print(first.value)  // 20
print(second.value) // 20
```

`first` і `second` тут вказують на один об'єкт. Тому зміна через `second` видима і через `first`. `let` забороняє переприсвоїти саму змінну, але властивість об'єкта все одно може змінюватися, якщо вона оголошена як `var`.

У структурах значення копіюється при присвоєнні, а в класах копіюється посилання. Для багатьох стандартних колекцій Swift застосовує оптимізацію copy-on-write: фізична копія відкладається до моменту зміни. Це не змінює правила, які ти бачиш у коді.

### Що обрати: `struct` чи `class`?

Починай зі `struct`, якщо описуєш самостійне значення: книгу, координату, налаштування або результат обчислення. Обирай `class`, якщо кілька частин програми мають навмисно бачити й змінювати один спільний об'єкт.

Не обирай `class` лише тому, що він здається «потужнішим». Спільний стан може ускладнити пошук помилок. Якщо об'єкту потрібна спільна ідентичність або спільні зміни — тоді посилання класу виправдане.

## Як думати над задачею

Перед написанням коду постав собі три питання:

1. **Що я описую?** Випиши іменники: книга, автор, статус. Іменники часто стають типами або властивостями.
2. **Які значення дозволені?** Якщо варіантів мало й вони відомі наперед, використай `enum`, а не довільний `String`.
3. **Чи має копія бути незалежною?** Для незалежної копії зазвичай підходить `struct`. Якщо два посилання повинні бачити одну зміну — розглянь `class`.

Потім додай лише потрібні властивості, створи один екземпляр і перевір його на маленькому прикладі. Не починай із великої програми: спочатку переконайся, що модель правильно передає твою ідею.

## Запуск прикладу

Ці команди запускають підготовлений приклад уроку з кореневої папки курсу. PowerShell — командний рядок Windows, а Bash — типовий командний рядок Linux/macOS. `./` означає «запустити файл із поточної папки».

Windows / PowerShell:

```powershell
.\scripts\run-example.ps1 06-structs-enums
```

```bash

```

Якщо shell повідомляє, що файл не знайдено, спочатку перейди в кореневу папку курсу. Якщо macOS забороняє запуск скрипта, не змінюй код навмання: перевір шлях і права файлу або запусти приклад із рекомендованого середовища курсу.

## Типові помилки

- **Зміна властивості `let`.** Помилка виникає, бо `let` робить властивість незмінною. Якщо значення має змінюватися, оголоси його як `var` ще до створення екземпляра.
- **Зміна властивості через екземпляр, оголошений як `let`.** Для структури `let book = ...` робить увесь екземпляр незмінним. Використай `var book`, якщо треба змінювати його `var`-властивості.
- **Пропущений `case` у `switch`.** Перелічення має скінченний набір варіантів, тому додай гілку для кожного з них. Не маскуй помилку `default`, якщо тобі важливо обробити кожен стан.
- **Плутанина між `struct` і `class`.** Якщо після присвоєння зміна однієї змінної несподівано впливає на іншу, перевір, чи не використовуєш клас там, де потрібні незалежні значення.
- **Невірний тип під час створення.** `pages` має бути `Int`, тому передавай число без лапок: `pages: 240`, а не `pages: "240"`.
- **Метод не бачить властивість.** Перевір написання імені та те, що властивість оголошена всередині того самого типу. Swift розрізняє великі й малі літери.

Відповідай без підглядання в код:

- Що таке value semantics і reference semantics?
- Чому `switch` з enum може бути перевірений компілятором на повноту?
- Яка різниця між властивістю `let` і `var`?
- Коли зміна через другу змінну буде видима через першу?

Ти готовий рухатися далі, якщо можеш пояснити різницю між `struct` і `class` власними словами, написати `enum` із повним `switch`, а також виконати практичне завдання без копіювання готового рішення. Додатково перевір себе запуском: програма має скомпілюватися, надрукувати опис книги й показати очікувану різницю між копією структури та спільним екземпляром класу.
